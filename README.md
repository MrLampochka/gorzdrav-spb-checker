# Горздрав СПб: проверка талонов с оповещением на email

Скрипт периодически спрашивает у API [gorzdrav.spb.ru](https://gorzdrav.spb.ru), есть ли свободные места для записи, и присылает письмо, когда они появляются.

Следить можно:

- за конкретным врачом;
- за несколькими врачами;
- за **всей специальностью** в медучреждении — тогда письмо придёт про любого освободившегося врача.

Зависимостей нет: только стандартная библиотека python 3.10+. Ни venv, ни pip не нужны.

## Быстрый старт

```sh
cd gorzdrav-email-checker
cp .env.example .env         # прописать почту
python3 checker.py --check-email     # проверить, что почта настроена
python3 checker.py --once --dry-run  # посмотреть, что находит, без письма
python3 checker.py --once            # разовая проверка с отправкой письма
python3 checker.py                   # цикл: проверка раз в 5 минут
```

## Настройка почты

Настройки лежат в `.env` рядом со скриптом (см. `.env.example`):

Параметр | Описание
-- | --
`SMTP_HOST` | адрес smtp сервера (`smtp.mail.ru`, `smtp.yandex.ru`, `smtp.gmail.com`)
`SMTP_PORT` | порт, по умолчанию `465`
`SMTP_USER` | логин на smtp сервере
`SMTP_PASSWORD` | пароль. Для mail.ru, яндекса и гугла нужен **пароль приложения**, а не основной пароль от ящика
`EMAIL_FROM` | отправитель, по умолчанию равен `SMTP_USER`
`EMAIL_TO` | получатели через запятую
`SMTP_SSL` | `true` — ssl (порт 465), `false` — starttls (порт 587). По умолчанию определяется по порту
`CHECK_INTERVAL_SECS` | период проверки в секундах, по умолчанию `300`
`COOLDOWN_HOURS` | сколько часов не повторять письмо про того же врача с теми же талонами, по умолчанию `6`
`WATCHES_FILE` | файл со списком отслеживаний, по умолчанию `watches.json` рядом со скриптом
`STATE_FILE` | файл с историей отправленных писем, по умолчанию `state.json`
`LOG_LEVEL` | `INFO` или `DEBUG`

Комментарий в конце строки (` # ...`) не попадает в значение. Если решётка нужна внутри пароля — возьмите значение в кавычки.

Проверить настройки, ничего не отправляя:

```sh
python3 checker.py --check-email
```

## Что отслеживаем

`watches.json` — список проверок:

```json
[
  {
    "name": "Терапия, поликлиника №1",
    "districtId": "2",
    "lpuId": 1054,
    "specialtyId": "98"
  },
  {
    "name": "Конкретный врач по ссылке с сайта",
    "url": "https://gorzdrav.spb.ru/service-free-schedule#...",
    "limitDays": 14
  },
  {
    "name": "Только нужные врачи по фамилии",
    "lpuId": 1054,
    "specialtyId": "98",
    "doctorNames": ["Иванов", "Петрова"],
    "email": ["other@example.com"]
  }
]
```

Поле | Описание
-- | --
`name` | название для письма и логов, необязательное
`url` | ссылка с сайта горздрава: из неё берутся район, лпу, специальность и врач (если он в ссылке есть)
`districtId` | ид района, нужен для корректной ссылки в письме
`lpuId` | ид медучреждения, обязателен если нет `url`
`specialtyId` | ид специальности, обязателен если нет `url`
`doctorIds` | список ид врачей. Пусто — следим за всеми врачами специальности
`doctorNames` | фильтр по части фамилии или имени, без учёта регистра
`anyDoctor` | `true` — следить за всей специальностью, даже если в `url` указан врач
`limitDays` | искать талоны только в пределах N дней от сегодня (1 — это сегодня)
`email` | получатели для этого отслеживания, если нужны не те, что в `EMAIL_TO`

Если файла нет, при первом запуске он создастся с примером.

## Как узнать идентификаторы

Проще всего выбрать врача на сайте горздрава и вставить ссылку из адресной строки в поле `url`. Либо найти id через сам скрипт:

```sh
python3 checker.py --list-districts           # районы
python3 checker.py --list-lpus 2              # медучреждения района 2
python3 checker.py --list-specialties 526     # специальности в лпу 526
python3 checker.py --list-doctors 526 92      # врачи по специальности
```

Первая колонка в выводе — нужный идентификатор.

## Когда приходят письма

Скрипт помнит в `state.json`, про каких врачей уже написал, и не шлёт одно и то же на каждой проверке. Письмо придёт снова, если:

- изменилось количество мест, талонов или ближайший талон;
- у врача пропали места, а потом появились снова;
- прошло `COOLDOWN_HOURS` часов с прошлого письма.

Если задан `limitDays`, скрипт проверяет реальные талоны врача и молчит, пока среди них нет ни одного в нужном окне. Без `limitDays` достаточно того, что у врача есть свободные места.

## Запуск по расписанию

Разовая проверка раз в 5 минут через cron:

```sh
*/5 * * * * cd /opt/gorzdrav-email-checker && /usr/bin/python3 checker.py --once >> checker.log 2>&1
```

Или как служба systemd на сервере (`/etc/systemd/system/gorzdrav-email.service`):

```ini
[Unit]
Description=Gorzdrav email checker
After=network-online.target

[Service]
WorkingDirectory=/opt/gorzdrav-email-checker
ExecStart=/usr/bin/python3 /opt/gorzdrav-email-checker/checker.py
Restart=always
RestartSec=60

[Install]
WantedBy=multi-user.target
```

## Из чего состоит

Файл | Что делает
-- | --
`checker.py` | точка входа: разбор аргументов, список отслеживаний, история писем, цикл проверок
`gorzdrav.py` | клиент API горздрава на стандартной библиотеке
`notifier.py` | отправка письма по smtp и его вёрстка
`settings.py` | чтение `.env` и настроек
`tests.py` | тесты, сеть не нужна

## API горздрава

Описание: [SPB Gorzdrav API Documentation](https://github.com/egorantonov/gorzdrav/wiki/SPB-Gorzdrav-API-Documentation)

Важная особенность: количество свободных талонов в списке врачей (`freeParticipantCount`) может не совпадать с реальным списком талонов (`appointments`) — бывает и так, что в списке мест нет, а талоны есть, и наоборот. Поэтому при `limitDays` скрипт всегда перепроверяет талоны отдельным запросом.
